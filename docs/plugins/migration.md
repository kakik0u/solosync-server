# プラグインmigrationと有効化

プラグインは `plugins/<id>/migrations/001_initial.sql` のような番号順のSQLファイルを同梱します。固有テーブルには `plugin_<id>_` の接頭辞を付けます。テーブル・索引はプラグインのファイルで定義し、サーバー本体の `migrations/` に追加しません。

初回ONでは、ホストが必要な共通capabilityを準備し、プラグインの未適用SQLを実行してからルート・イベントを有効にします。`plugin_schema_migrations` にファイル名とSHA-256 checksumが記録されます。適用済みファイルを編集せず、新しい変更は次の番号のファイルに追加します。途中で失敗した場合はOFFのままになり、管理画面にエラーを表示します。DDLの自動rollbackを前提にしないため、migrationは再実行可能な `CREATE TABLE IF NOT EXISTS` などを使ってください。

OFFではテーブルを削除しません。再ONでは適用済みファイルを飛ばします。プラグインのファイルがなくなっても、データは自動削除しません。バージョンが変わった場合は、新コードのHTTP/event実行を止め、管理者が再度ONにしてmigrationを通す必要があります。

共有ホストのDBユーザーにはテーブル作成権限が必要です。プラグインmigrationはそのDBユーザーで実行されるため、信頼できるPHP/SQLだけを配置してください。専用の空DB以外で破壊的な統合テストを実行しないでください。
